## Rec 1 — update-pnl DB-fault resilience + honest PARTIAL line (`scripts/update-pnl.ts`)

**Bug:** the Sep 9 08:19 run hit a transient SQLite connector error
(`Error code 1: SQL error or missing database`) inside the mark transaction;
738/1,786 open trades were marked (41%) yet the run still logged "complete".

**Fix:**
- `withDbRetry()` — every DB mutation in the loop (mark / resolve / expire /
  recycle) retries up to 3× with 500ms/1s backoff on transient SQLite
  signatures (`SQL error|connector|database is locked|timeout|busy`).
- Coverage accounting: `covered = updated+resolved+expired+recycled` vs
  `open.length`. < 90% → explicit `PnL update PARTIAL: X/Y covered` via
  logError **and non-zero exit** (cron alert); unmarked trades re-mark next
  hourly run. Otherwise the completion line now reports
  `N/M covered (X%)`.
- Live-verified: `PnL update complete: 1771 updated … 1771/1773 covered (100%)`, exit 0.
